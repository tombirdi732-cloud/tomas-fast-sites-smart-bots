# Как заведения получают доступ к панели

Две двери. Обе ведут в одну и ту же панель, разница — кто кого проверял.

## Дверь 1: приглашение (основной путь)

Вы поговорили с рестораном, посмотрели документы, договорились о комиссии.
Дальше:

1. Админка → **Заведения** → «Пригласить заведение» → **Выписать код**.
   В поле «Для кого» пишете, кому код, чтобы потом не гадать.
2. Код вида `YE3SE73T` (8 символов, без похожих друг на друга букв —
   его диктуют по телефону) действует 14 дней и срабатывает один раз.
3. Заведение открывает панель, входит по своему номеру телефона,
   заполняет форму регистрации и вводит код.
4. Заведение сразу получает статус `approved` и может выставлять боксы —
   очередь модерации оно минует, потому что проверяли вы лично.

Использованный код повторно не сработает: вернётся `INVITE_USED`.

## Дверь 2: самостоятельная заявка

Заведение находит панель само и подаёт заявку без кода. Оно попадает
в статус `pending` и до одобрения выставлять боксы не может.

При подаче заявки API сам дёргает реестр ФНС по ИНН (DaData, `findById/party`)
и складывает ответ в `merchants.verification`. В админке он показан рядом
с тем, что заведение написало в заявке:

- название, ОГРН, форма (ИП или юрлицо), руководитель, юридический адрес;
- «Организация действующая» — или её статус, если она ликвидирована;
- предупреждение, если название в заявке не похоже на название в реестре.

Это подсказка, а не решение. Одобряет человек — кнопкой «Одобрить».
Отказ и приостановка требуют текста причины: его увидит заведение.

Если `DADATA_TOKEN` не задан, автопроверка выключена и в карточке висит
напоминание сверить ИНН вручную на egrul.nalog.ru.

## Внутри заведения: владелец и кассиры

Тот, кто зарегистрировал точку, становится **владельцем** (`merchant_staff.role
= 'owner'`). Он один может менять карточку заведения, выставлять боксы и
управлять составом смены.

Кассир добавляется тем же механизмом: **Сотрудники** → «Пригласить кассира»
→ код на 7 дней. Кассир входит по своему телефону, вводит код на вкладке
«У меня есть код» — и получает доступ к заказам и выдаче по коду
покупателя. Карточку заведения и боксы он трогать не может: `PATCH`
вернёт 403.

Владельца из состава убрать нельзя — заведение осталось бы без хозяина
(`CANNOT_REMOVE_OWNER`).

## Что где в коде

| | |
|---|---|
| Логика доступа | `apps/api/src/merchants/access.service.ts` |
| Эндпоинты | `apps/api/src/merchants/access.controller.ts` |
| Проверка ИНН | `apps/api/src/merchants/inn-check.service.ts` |
| Экран модерации | `apps/web/src/pages/AdminMerchantsPage.tsx` |
| Экран сотрудников | `apps/web/src/pages/StaffPage.tsx` |

Всё, что делает панель, проходит через `requireAccess` (владелец или
кассир) либо `requireOwner` (только владелец) — мимо этих проверок
в заведение попасть нельзя.
